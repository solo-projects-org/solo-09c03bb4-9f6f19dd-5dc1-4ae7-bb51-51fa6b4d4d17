## 发布语义

- 每个批次的原档保存于 `data/originals/<batch_id>/original.csv`，与判定在同一 SQLite 事务中提交。
- 查询页与下载接口按船舶 `version` 取快照：并发上传或重启后只会看到完整版本。
- 若整个文件没有任何可接受行，接口返回 422，批次不发布，既有航迹不受影响。

## 站日对账样例（SZ01 / 2026-01-01）

| 文件 | 场景 |
| --- | --- |
| `recon_clean_sz01_20260101.csv` | 三行全部是 SZ01 在 2026-01-01 的定位、无拒绝行——**内容合格**档。 |
| `recon_mixed_sz01_20260101.csv` | 混入一条 HK02 他站定位、一条次日（2026-01-02）定位和一条解析拒绝行——**内容不合格**档。 |
| `recon_manifest_sz01_20260101.txt` | 上游交接清单（`sha256sum` 格式），只含合格档的 SHA-256，可直接粘贴进对账页文本框。 |

手工验证：

1. 上传 `recon_clean_sz01_20260101.csv`，打开 `站日对账 → SZ01 → 2026-01-01`，
   把 `recon_manifest_sz01_20260101.txt` 的内容粘入清单并保存：显示**可交接**。
2. 再上传 `recon_mixed_sz01_20260101.csv`（无需改清单）：结论变为**不可交接**，
   该档列为**清单外档**，并列出“含 1 行解析拒绝行 / 他站 1 行 / 同站他日 1 行”。
3. 再把同一合格档原档重传一次：出现**重复收档**，仍不可交接；把不存在的
   SHA-256 写入清单则出现**缺档**。
4. 打开页面后另开标签页上传新批次，再回到旧页面提交：返回 **409 旧页面提交被拒绝**，
   已保存的清单保持不变。
